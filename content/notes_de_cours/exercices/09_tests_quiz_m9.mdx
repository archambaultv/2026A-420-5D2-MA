# Exercice 8 : tester Quiz M9

:::info

Ceci est un exercice formatif. Il n'y a rien à remettre.

:::

L'objectif est de remplacer le harnais `npm run verifier` par des tests
unitaires et d'intégration. Notes à garder ouvertes : [Tester avec
node:test](/notes_de_cours/qualite/tests_node).

## Étape 0 : partir du bon pied

```bash
git checkout main
git pull
git checkout -b sem-04
npm install
npm test
```

Le rapport doit finir par `pass 7`, `fail 0`, `todo 9`. Les `todo` sont
votre travail.

## Jalon 1 : les cas limites de `calculateScore`

- **Fichier** : `server/test/scoring.test.js`

Les cinq premiers tests sont ceux du harnais, réécrits. Les cinq `test.todo`
nomment des cas limites ; remplacez chacun par un vrai test.

**Vérifier.** `npm test` : `todo 4`, aucun `fail`. Cassez volontairement
`scoring.js` (un `4` à la place du `5`) : combien de tests deviennent
rouges ? Remettez le `5`.

## Jalon 2 : l'espace auteur, en HTTP

- **Fichier** : `server/test/quizzes.test.js`

Le premier test est fourni ; lisez `helpers.js` pour voir d'où vient
`api`. Trois `test.todo` : une question sans bonne réponse est refusée,
une question avec deux bonnes réponses est refusée, une question valide
apparaît dans `GET /api/quizzes/:id`.

**Vérifier.** `npm test` : `todo 1`. Les tests ne touchent pas votre
`quizm9.db` : `npm run dev` peut tourner en même temps.

## Jalon 3 : d'abord le test qui échoue

- **Fichiers** : `quizzes.test.js`, puis `server/src/app.js`

Le bogue : créer un questionnaire, ne pas lui ajouter de question, et lancer
une partie dessus. Une fois lancée, la partie se termine immédiatement.

 Écrivez le test : `POST /api/games` sur ce
questionnaire doit répondre `400`. Lancez-le : il **doit échouer** (l'API
répond `201`). Ensuite seulement, corrigez la route dans `app.js`, et
relancez.

**Vérifier.** `npm test` : `pass 16`, `fail 0`, `todo 0`. Dans le
navigateur, créer une partie sur un questionnaire vide affiche le message
d'erreur sous le bouton.

## Jalon 4 : pour les rapides

Un fichier `games.test.js` : rejoindre deux fois la même partie avec le
même pseudonyme est refusé ; rejoindre une partie commencée est refusé.

## En panne ?

- `EADDRINUSE` : un test a appelé `app.listen(3000)` au lieu de passer
  par `startServer`, ou `server.js` a été importé au lieu de `app.js`.
- Les tests d'intégration voient les questionnaires de votre base :
  `DB_PATH` est fixé après l'import de `app.js`. L'ordre compte.
- Un test passe seul et échoue avec les autres : il dépend de ce qu'un
  autre test a écrit dans la base. Chaque test crée ce dont il a besoin.
- `assert.equal(data.error, …)` échoue avec `undefined` : `data` est
  `null`, la réponse n'était pas du JSON. Affichez `status` d'abord.
